# MVP deployment and operational contract

The target local topology is Reliability API plus worker, Observability collector/query API plus dashboard, PostgreSQL, and a PostgreSQL-backed durable job/outbox mechanism under ADR-009. An implementation may co-locate processes, but must retain independent failure boundaries. No Kafka, Kubernetes, vector DB or separate Interaction Store is required. `docker compose up` is a target acceptance test, not an existing command in these documentation-only repos.

Required configuration: public/internal bind addresses, authenticated tenant/project seed, provider secret reference, capture mode, retention by data class, payload and queue limits, request/worker deadlines, retry policy, storage connection, cost pricing source/version, and exporter endpoints. Provide a committed example configuration with nonproduction placeholders, `.env.example`, migrations, seeded sample tenant and a smoke test when the runtime is implemented. No real provider credential is committed. Readiness checks storage/queue dependencies; liveness checks process health. Emit version/build metadata, ingress and evaluation rates, latency, queue depth/age, retry/drop counts, provider errors, query latency and redaction failures.

Availability rules: SDK telemetry is best effort and bounded; evaluation API errors are explicit; dashboard outage does not stop ingestion; provider failure yields abstention or a typed operational failure, never a factual fail. Jobs use bounded retry and terminal inspectability. Define backup/restore and migration rehearsal before production deployment. Measure baseline ingestion throughput, evaluation latency, query latency and resource footprint before adding distributed infrastructure. Enterprise deployment can replace identity, secrets and persistence behind the same ports.
