# Prototype migration notes

> Historical migration snapshot, with a follow-up wire-shape/scoring/port pass applied 2026-09-13. The architecture [CURRENT_IMPLEMENTATION.md](../CURRENT_IMPLEMENTATION.md) is the checked status. The weighted "reliability" score and flat `VerificationScores` this note originally praised are **gone** -- CONTRACTS.md has no such aggregate, and the code no longer has one. See "Update 2026-09-13" at the end of the gaps list below for exactly what changed and what is still open.

**Source:** `/Users/anireddy/Documents/Projects/claude-ai/fact-lama` (a pre-pivot, single-repo `factlama` package built before the architecture/reliability/observability split and before ADR-004/006/010–015). Not a git repository; copied, not moved — the original is untouched.

**What this is:** a working, tested (116 passing, 1 skipped) reference implementation of claim extraction, evidence mapping, scoring, and policy evaluation. It is a real head start on REL-03 through REL-09, not a finished implementation of them. It predates `CONTRACTS.md` v0.1 and every ADR from 004 onward, so its wire shapes and provider interface diverge from what this repository now owns. Nothing here should be marked `COMPLETE` in `docs/implementation.md` on the strength of this migration alone.

Import paths were mechanically rewritten twice: first `factlama.*` → `factlama_reliability.*` during the initial copy, then flattened again to bare `schemas.*`/`core.*`/`judges.*` once the layout moved from a single `src/factlama_reliability/` package to top-level `schemas/`, `core/`, `judges/` packages (no `src/` wrapper), matching this README's "Target module layout" literally. `core/__init__.py` re-exports `verify`/`Verifier` and the other core symbols, so `from core import verify` is the top-level convenience entry point — there is no longer a single all-encompassing `factlama_reliability` package to import from. Everything else is unchanged prototype code.

`evidence/`, `agents/`, `models/`, and `api/` from the target layout were not created — nothing migrated needs them yet, and the README is explicit that the target layout is "not permission to create every directory immediately."

## What did not move, and why

- **`architecture docs/FactLama_SLM_Solution_Details.md`** (2091 lines) — the old SLM-centric platform thesis. It predates and is superseded by `factlama-architecture`'s ADR-006/ADR-010 (SLM as one benchmark-gated evaluator among many, not the platform). Importing it into this repo as a doc would plant a second, conflicting narrative next to the authoritative one. Left in place at the source path for historical reference only.
- **`architecture docs/FactLama_Schemas_and_Core_Specification.md`** (1369 lines) — superseded by `factlama-architecture/CONTRACTS.md`, which is now the single source of truth for wire shapes. Same reasoning: not imported, left at the source path.
- **Nothing moved to `factlama-observability`** — the old project had no collector, telemetry pipeline, storage, or dashboard code. `schemas/telemetry.py` is a single Pydantic model for OTEL-attribute export, migrated with the rest of `schemas/`; there was no separate observability component to place.

## Gaps to close before this counts as REL-03..REL-09 (in the order they'll be hit)

1. ~~**Wire shape mismatch with `CONTRACTS.md`.**~~ **Closed 2026-09-13** for the fields CURRENT_IMPLEMENTATION.md named: `VerificationRequest.context` is now `evidence`, `tenant_id` is no longer a request field at all (tenant is a trusted `Verifier.verify(request, tenant_id=...)` argument, never client payload), `question` is optional, `project_id`/`application_id` are required, `interaction_id`/`trace_id`/`span_id`/`model`/`prompt_version`/`policy_id` are accepted. `VerificationResult` now has `evaluation_id`, `status` (`COMPLETED|ABSTAINED|FAILED`), `abstention_reason`, and a structured `provenance` object with `attempts[]`. `scores` is now `dict[str, ScoreValue]` (`{value?, status, method_version, calibration_class}`) instead of flat floats. **Not closed**: `Evidence.id`/`extracted_text` are still not `evidence_id`/`content`+`reference`; `ClaimVerification.evidence` is still evidence-reference objects with support/relevance scores, not a plain `evidence_ids` list plus `contributing_judgments`; `DISPUTED` status and multi-judge reconciliation are still absent (correctly -- ADR-015 defers them). `tool_executions` was renamed to match CONTRACTS.md naming as part of this pass.
2. ~~**`ModelProvider` does not match the `JudgeProvider` port.**~~ **Closed 2026-09-13.** The class is renamed `JudgeProvider`; its one required method is now `evaluate(JudgeRequest, deadline, cancellation) -> JudgeResult`, checking cancellation/deadline before dispatch and returning a typed `JudgeError` (`TIMEOUT|RATE_LIMIT|UNAVAILABLE|INVALID_RESPONSE|CANCELLED|CONFIGURATION`) instead of raising. `extract_claims()` is removed from the interface and every subclass -- claim segmentation is exclusively `core.claims`'s job now. `evaluate_instruction`/`evaluate_scope` remain as optional, non-abstract extras (not part of the formal contract port).
3. **`EmbeddingProvider`/`NLIProvider` are a genuine asset for ADR-011's T0 tier.** Unchanged assessment: real, working, non-SLM, non-frontier judges, now behind the `evaluate()` port like every other provider.
4. ~~**No provenance/calibration fields.**~~ **Closed 2026-09-13** for the MVP one-attempt-per-claim shape: every judge dispatch produces an `Attempt` (`attempt_id`, `provider_id`, `qualification_status` hardcoded `UNQUALIFIED` -- no registry exists to say otherwise, `calibration_class` from a new deterministic `derive_calibration_class()` per ADR-010's formula, `outcome`, `usage`). `qualification_status`/`calibration_class` are real and derived, not placeholders pretending to be something else, but there is still no qualification harness or registry behind them (G4, unstarted). ~~**Open ambiguity**: CONTRACTS.md's worked example shows one attempt covering two claims...~~ **Resolved 2026-09-13 at G0**: CONTRACTS.md now states explicitly that one `JudgeProvider.evaluate()` call maps to exactly one `Attempt`, and its worked example was rewritten to show two attempts for its two claims (`contracts/v0.1/examples/valid/verification_result/partial.json` is the canonical copy). This implementation's one-attempt-per-claim behavior was already correct; only the contract's own worked example was wrong.
5. **No tenant enforcement beyond a trusted parameter (blocks REL-02).** `tenant_id` is now correctly kept out of the request payload and passed as a trusted `Verifier.verify()` argument, but there is still no actual authentication/authorization layer, no cross-tenant isolation test against persistence (there is no persistence yet), and no secret/credential boundary. This closes the specific "trusted from an unverified payload" bug CURRENT_IMPLEMENTATION.md named, not REL-02 as a whole.
6. **Synchronous only (blocks REL-10).** Unchanged: no job/idempotency model; `verify()` is a direct call.
7. **No budgets (relevant to ADR-012).** Unchanged: claim segmentation is unbounded; no `MAX_CLAIMS_PER_REQUEST`, no per-tenant-window budget, no `BUDGET_EXHAUSTED` abstention reason (deliberately omitted from `AbstentionReason` in this pass, since nothing produces it yet).
8. **OTEL attribute keys use a `factlama.*` namespace** (`schemas/telemetry.py`), deliberately left untouched again in this pass -- still needs reconciliation with `ai.reliability.*` before wiring to a real exporter.

### Update 2026-09-13: scoring formula and verdict computation rewritten

The prototype's weighted composite (`0.35`&nbsp;groundedness + `0.20`&nbsp;citation_support + ... minus hallucination/contradiction/scope risk penalties, clamped to `[0,1]`) is deleted. It was a real, working heuristic, but CONTRACTS.md has no such aggregate, and its risk-penalty logic was also silently deciding the aggregate verdict (a violation's severity could upgrade `PARTIAL` to `FAIL`), which conflicts with "factual verdict is computed independently of policy action." Replaced with:

- `groundedness`/`hallucination_risk`/`contradiction_risk`: exact claim-ratio formulas from `scoring.md` (count of matching applicable claims / count of applicable claims; `NOT_APPLICABLE` when the denominator is zero; no partial credit for `INSUFFICIENT_EVIDENCE`).
- `citation_support`/`tool_correctness`: kept as deterministic structural scores (unchanged math), but now `NOT_APPLICABLE` rather than an optimistic `1.0` when no citations/tools were supplied.
- `scope_breach`/`instruction_adherence`/`confidence_alignment`: now always `UNAVAILABLE` -- scoring.md defines no v0.1 formula for these, so the prototype no longer invents one. The underlying violation detection (`SCOPE_BREACH`, `INSTRUCTION_VIOLATION`) is unchanged and still runs; only the numeric score dimension was removed.
- A new `core.scoring.determine_verdict()` implements scoring.md's PASS/PARTIAL/FAIL/ABSTAIN precedence directly from claim verdicts, independent of policy. `PolicyEngine.evaluate()` no longer computes or upgrades the factual verdict -- it takes the verdict as input and returns only a policy action and threshold violations.
- A practical consequence worth flagging: "no evidence supplied" no longer means "assume PASS with perfect groundedness." Every claim without evidence now genuinely gets `INSUFFICIENT_EVIDENCE` from the provider, `groundedness=0.0` (not `1.0`), and the result `ABSTAIN`s. This is more honest but is a visible behavior change from the original prototype and from this document's own earlier text.

## What's already right and worth keeping exactly as-is

- The verdict and violation vocabulary matches `CONTRACTS.md` and this repo's README verbatim: `SUPPORTED|CONTRADICTED|UNSUPPORTED|INSUFFICIENT_EVIDENCE|NOT_APPLICABLE`, `PASS|PARTIAL|FAIL|ABSTAIN`, and the violation codes overlap almost exactly.
- ~~The scoring weights in `ScoringEngine`...~~ **Superseded 2026-09-13**: the weighted composite described here is deleted (see "Update 2026-09-13" above) because it conflicted with CONTRACTS.md having no such aggregate and with verdict independence from policy. `scoring.md`'s claim-ratio formulas replace it.
- `Verifier._evaluate_citations` and `_evaluate_tools` are still deterministic/structural rather than model-judged (matching `evidence-engine.md`'s "similarity is routing only" philosophy) — unchanged by this pass.
- The `abstain on error` fail-closed default is still correct and is now more precise: a truly unexpected pipeline failure produces `status=FAILED`, `verdict=ABSTAIN`, a typed `abstention_reason`, and a generic `metadata={"failure": "internal pipeline error"}` -- the real exception is logged via `logging`, never returned in the public result (content governance), where the original prototype put `str(exception)` directly into public metadata.
