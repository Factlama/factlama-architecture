# Optional Interaction Store design

ADR-008 defers implementation. The future port stores tenant-scoped interaction records linked by `interaction_id`, trace ID and evaluation ID, separate from telemetry and evaluation metadata. Content classes are prompt, response, evidence, tool arguments/results and raw judge output; each has an independent capture switch. A stored object records capture policy version, redaction version, creation/expiry, encryption key reference and origin. Absence of an object is normal and must not break trace/reliability views.

Writes are authorized and redacted before durability, including queues, logs and indexes. `FULL` requires explicit tenant opt-in; provider credentials are never storable. Reads require a content-specific permission and are audited. Retention/deletion must cover primary objects, replicas, search indexes, exports and derived datasets. Replay creates a new evaluation ID and preserves lineage to the original interaction, evaluator/prompt/model/config versions and evidence snapshot; it cannot silently overwrite production results. Dataset conversion requires consent, de-identification and separate retention. No MVP service may require this port to be configured.

Under default metadata-only capture, there is no retained answer/evidence snapshot to re-score against a changed judge. A tenant must opt into enough governed content capture before production traffic if later cross-version re-evaluation is required. A new evaluation records `supersedes` and its own calibration class; old results are immutable.
