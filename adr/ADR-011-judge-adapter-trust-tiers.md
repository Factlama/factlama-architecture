# ADR-011: Judge Adapter Trust Tiers

Status: Proposed

Decision: Judge adapters are split into three trust tiers. **T0 (first-party)**: FactLama-authored adapters (e.g. openai, anthropic, azure), in-process, under FactLama code review and CI. **T1 (certified partner)**: in-process but signed, version-pinned, code-reviewed, with a conformance run and an agreement report (ADR-010) on file before an operator installs them. **T2 (customer judge)**: out of process, always. FactLama publishes `JudgeProvider` as an HTTP wire schema — a small step from the existing one-claim-in/one-verdict-out port in CONTRACTS.md — and the customer operates the endpoint. FactLama calls it over mTLS through an egress proxy enforcing a per-provider host allowlist, a bounded payload size, and a hard deadline; the endpoint never receives FactLama's database connection, job queue, or any secret beyond what the call itself requires. Secret resolution is authorized per call, scoped to `(tenant_id, provider_id)` for the evaluation in flight — not a general-purpose lookup available to adapter code. Free-text judge rationale is rendered as inert text in the dashboard, never as HTML or markdown capable of producing links or images.

Rationale: "Any judge" means third-party code or third-party endpoints in the verdict path, and this had no documented answer. An in-process custom adapter would hold the same privileges as first-party code — the shared connection pool, every tenant's secrets, unrestricted egress — which makes EPIC-02's "cross-tenant access fails safely" exit criterion unverifiable, because tenant isolation in a shared process is an application-code property and the adapter is application code. Moving T2 out of process converts a code-trust boundary FactLama cannot enforce into a network boundary it can, and does so without requiring FactLama to review third-party code — which is what lets the ecosystem in ADR-004/ADR-006 actually scale.

Consequences: EPIC-04's first adapter is T0 and unaffected. EPIC-07's "second/custom provider path" must ship the T2 HTTP wire schema and egress proxy, not an in-process extension point, before opening to customer-supplied judges. `SECURITY_MODEL.md`'s threat-test list gains adapter-tier entries (SSRF via adapter-controlled base URL, secret over-scoping, supply-chain risk in T1 code) that today assume only first-party code. `judge-provider.md` states per-claim isolation as a security property, not just a pipeline detail, since it bounds an injection payload's blast radius to one claim's verdict.
